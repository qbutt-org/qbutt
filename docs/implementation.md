# План qbutt, qplay и qcatch

Актуально на 15 октября 2026. Разработка и выпуск поставлены на паузу по просьбе пользователя. Опубликованы qbutt 1.5.3, qplay 1.2.0 и qcatch 1.1.0. Финальный установщик qbutt 1.5.3 проверен в VM без Qt SDK: поиск, автоматическое объединение источников и выбор точного варианта. Публичные installer и ZIP сверены по хешам. Исходники будущего 1.5.4 сохранены; эта версия не опубликована. Последняя правка скрытия подтверждённо пустых карточек ещё требует финального прогона. Временные сборки и копии стендов удаляются для освобождения диска; при возобновлении их нужно пересобрать.

Цель: законченные поиск, скачивание, просмотр и чтение на Rust/QML, удобные самостоятельные qplay/qcatch и согласованная работа трёх продуктов. Приоритет — поиск qbutt. Перенос стека сам по себе не завершает функцию.

## Как пользоваться планом

Обновлять очередь и остаток на месте. Диагностика остаётся рядом со стендом, история — в Git; команды, хеши, временные пути и пересказы прогонов сюда не добавляются. «Реализовано», «проверено на стенде» и «принято в пользовательском пути» различаются.

Долговременные правила — [AGENTS.md](../AGENTS.md), границы ядра — [архитектура](qbutt-architecture.md), владельцы контента — [контракты](agents/content.md), воспроизводимые проверки — [tests/README.md](../tests/README.md). Эти документы не дублируются здесь.

## Что уже существует

- **qbutt:** внутрипроцессные Rust-сервисы, 29 сетевых провайдеров, QML-поиск/история/избранное/источники, библиотека, Share, прямые загрузки и reader. Категории и фильтры работают поверх накопленной выдачи. Bun/Go backend, Cardigann и их продуктовая упаковка удалены; часть старых модулей ещё используется только QA.
- **Чтение:** главы, режимы/fit, настройки, точная позиция, локальные книги, Codex-перевод и обратимый кеш. Есть ограниченный предпреревод следующей главы/страницы и обработка длинных изображений. Качество сложной манги ещё недостаточно.
- **qplay:** Rust/CXX-Qt/QML с libmpv, GPU policy, framegen, обновление инструментов, Save и перевод субтитров. Старый C#/Lua UI удалён. Свежая локальная установка без Qt SDK, открытие видео, pause/seek/resume и uninstall с сохранением данных приняты. Полная offline-установка ещё не доказана.
- **qcatch:** TypeScript-расширение и Rust host, самостоятельные загрузки и передача в qbutt/qplay. Приняты ограниченные direct/HLS/static-DASH пути; локальный installer и завершение setup CLI исправлены и проверены.

## Архитектурные решения

Собственная прикладная логика живёт в Rust внутри qbutt; CXX-Qt даёт типизированную границу с Qt. QML отвечает за представление. C++ qBittorrent/libtorrent сохраняет session, peer I/O и storage; qbutt-net остаётся отдельным процессом. Нативные DPAPI и browser broker уже существуют. Переписывать всё ядро ради одного языка не требуется.

Qt 6.12, Quick Controls/Templates и общая палитра — текущая основа. StyleKit не принят для смешанного Widgets/Quick интерфейса: оформление дерева и заголовков не согласовано. Один QML shell через QQuickWidget должен покрывать область модального picker; отдельную накладку поверх соседних Widgets не добавляем. Проверки IME/DPI/стоимости рендера ещё открыты.

Проектные Qt Docs/Live Preview MCP настроены; подтверждение hot reload не является блокером продукта. Отдельная бесполезная preview-сцена удалена. Breaking changes допустимы; миграция старых профилей необязательна, сохранность payload и посторонних данных обязательна.

## Отбор и качество источников

Наш явный список допуска и отдельный читаемый Rust-модуль на провайдера. Внешние адаптеры служат референсом, не загружаются массово и не обновляют код/домены без проверки. Приоритет: RU/EN, полезные японские оригиналы; фильмы, аниме, игры, программы, манга, ранобэ и взрослые каталоги. Нерелевантные региональные, китайские, платные и устойчиво неработающие источники не переносим; у смешанных сайтов проверяем бесплатное покрытие.

Перед добавлением сверять канонический домен, полезность и [Megathread](https://www.reddit.com/r/Piracy/wiki/megathread/), включая [Unsafe Sites](https://www.reddit.com/r/Piracy/wiki/megathread/unsafe-sites/). Сохранённые исключения: thepiratebay.org, 1377x.to, yts.mx, watchsomuch.to, igg-games.com, steamunlocked.net, getintopc.com, haxnode.net. Похожие домены не считаются зеркалами автоматически.

Допуск требует полного search → inspect → resolve → действие, непервого варианта и применимых empty/error/cancel/retry/session сценариев. Один HTTP 200 или AddDialog → Cancel не доказывает законченную загрузку. Для проверки payload использовать контрольный материал; неизвестные игровые EXE запускать не нужно. Один timeout или CAPTCHA не служит основанием выбросить источник.

## Критерии завершения

### Поиск S1–S9

| ID | Требуемое поведение |
| --- | --- |
| S1 | Поступающие результаты видны сразу; есть прогресс и отмена. Медленный источник не удерживает выдачу, поздний ответ старого запроса её не меняет |
| S2 | Категория фильтрует накопленные и новые результаты без повторного запроса; возврат восстанавливает их |
| S3 | Алиасы RU/EN/ромадзи, пунктуация и release-хвосты объединяются при достаточном основании. Категории, ремейки, явные сезоны и неоднозначные работы не схлопываются |
| S4 | Видны известные серия/сезон, озвучка, язык, источник, качество, размер и версия. Неизвестное не выдумывается; исходные значения доступны для точного выбора |
| S5 | Ранжирование учитывает язык и качество; сиды сравнивают только торренты. Новые ответы не сбивают выделение и не переставляют строки постоянно |
| S6 | Карточка перечисляет источники с сокращением длинного списка. Таблица начинается с «Вариант» и иконки действия, затем источник, применимые размер/сиды |
| S7 | Варианты подгружаются автоматически с ограниченной параллельностью и прогрессом, включая поздние публикации. Нет ручного раскрытия каждой публикации; точный выбор сохраняется |
| S8 | Избранное отмечено красной закладкой. История хранит полную работу, последний вариант и фильтры; Share передаёт работу и предпочтительный вариант, сохраняя доступ к остальным |
| S9 | Сохранённая/общая ссылка после restart открывает ту же публикацию без молчаливой подмены. Действие начинается один раз, отказ запуска не создаёт успешную History |

S7 проверен в нативном стенде и нажатием в VM: поздние варианты загружаются автоматически, точный выбор и строка сохраняются; отказ источника не зацикливает запрос. Готовый вариант доступен во время чужой проверки; сохранённый ждёт обновления своей публикации, исчезнувший не подменяется.

S8/S9: в MainWindow общая ссылка Ready or Not сохранила все 17 доступных публикаций восьми источников и предпочтительную раздачу RuTor; AddDialog подтвердил её точный infohash. Недоступный DODI остаётся ошибкой источника без блокирующей модалки. Позднее подтверждение общего издания больше не теряет ранние публикации. Нативный стенд проверяет точный Retry, сохранение пользовательского выбора, отмену и полный отказ. Ошибки Runtime при Save теперь сохраняют конкретную причину; реальный отказ запуска показан в VM, отсутствие фиктивной загрузки и защита от запоздалой ошибки проверены в нативном стенде.

S6: канонический заголовок, краткий список источников с `+N` и выбор точных вариантов проверены в общем MainWindow в VM, Light, 1280×720 и 1440×900. Исходные названия раздач сохраняются в вариантах.

S3: исправлено ошибочное требование общего torrent hash для объединения продукта. В живом MainWindow `ready or not` объединяет девять источников игры, включая FreeTP/ByRut/Igruha; восемь дают варианты, DODI ограничен текущими хостингами. Фильтр FitGirl → точный `.torrent` → AddDialog принят. Посторонние результаты отфильтрованы, Online-Fix/ByRut/LimeTorrents/Igruha завершились без ошибок. Фильм 2019 года и сиквел сгруппированы отдельно. На реальных названиях проверены технические хвосты, языковые метки и качество в скобках. Строки без номера продолжения и новелла `The Deadline is coming!` остаются отдельно.

Дополнение S3 принято в живом MainWindow: публикации VK объединяются с фильмами по названию/алиасу и явному году, сохраняя точную запись и исходное название загрузки. Фильм 2019 года и сиквел объединяют RuTor, VK и Lime; выбор VK даёт просмотр/сохранение, непервый RuTor открывает точный AddDialog. Сиквелы, несовместимые сезоны и отрывки остаются отдельно. Нативный прогон обоих направлений разделения группы подтвердил сохранение выбора/фильтров: inspection не пишет библиотеку, явное действие атомарно разделяет записи, избранное остаётся у исходной карточки, точная история открывается у отделившейся публикации.

Явный update с версией и последующие полные сборки связываются по точному исходному названию подтверждённой публикации. В MainWindow новая сборка Lime без года и update входят в одну карточку игры; их исходные названия, размеры и точные варианты сохранены. Корпус проверяет порядок поступления, конфликтующие годы и отзыв подтверждающей публикации. ## Ресурсы и оставшаяся очистка

Бюджеты при сопоставимых условиях: первое видимое окно ≤2 с; два тёплых запуска ≤500 мс каждый; средняя private memory пустого дерева ≤250 MiB; idle CPU ≤2% ядра; каждый WM_NULL ≤50 мс без timeout. Бюджеты первого и тёплого запуска пока не приняты. Измерить первый результат, большие списки и предельный reader. Бюджеты ради прохождения не ослаблять.

Удалить потерявшие потребителей legacy QA-модули, Widgets/QSS/handlers, дубли runtime/profile/discovery и obsolete builds после принятия замены. Проверить отсутствие dev/test overrides в installer; оставшиеся предупреждения strict lint не скрывать новыми allow. Рост диска и длительный idle qcatch после установки ещё не исследованы.

До 20 агентов получают конкретные независимые срезы в отдельных worktree; root владеет общей интеграцией и этим планом. Предпочтение GPT-6.1 Sol/xhigh, разрешённый fallback — 6 Sol, при частых capacity-отказах Astra. Три переиспользуемых build slots, по два compiler jobs; SDK/зависимости общие, Cargo incremental отключён. При передаче слота исключать stale артефакты другого checkout и дубли runtime. Все GUI-проверки и управление браузером, включая чтение через Computer Use, — только в VM с одним владельцем; host UI не трогать. После проверки освобождать свои процессы, вкладки и ненужные файлы. Ссылки на общие модели/кеш не отменяют запрет reparse внутри продуктового runtime; не удалять их цели и не предполагать работоспособность DLL с SMB.
