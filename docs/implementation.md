# План qbutt, qplay и qcatch

Актуально на 4 ноября 2026. Опубликованы qbutt 1.6.11, qplay 1.4.2 и qcatch 1.3.8 для Windows и Linux x64. Linux-сборки рассчитаны на Ubuntu 24.04+ с glibc 2.39+. Текущий приоритет — надёжность загрузок и источников, qcatch и qplay. Читалка — последний приоритет: только критичные исправления, без доведения клининга до идеала.

Цель: законченные поиск, скачивание, просмотр и чтение на Windows и Linux, самостоятельные qplay/qcatch и согласованная работа трёх продуктов. Лендинги выбирают основной способ установки по ОС посетителя и сохраняют явный доступ к остальным сборкам. Перенос стека сам по себе не завершает функцию.

## Как пользоваться планом

Обновлять очередь и остаток на месте. Диагностика остаётся рядом со стендом, история — в Git; команды, хеши, временные пути и пересказы прогонов сюда не добавляются. «Реализовано», «проверено на стенде» и «принято в пользовательском пути» различаются.

Долговременные правила — [AGENTS.md](../AGENTS.md), границы ядра — [архитектура](qbutt-architecture.md), владельцы контента — [контракты](agents/content.md), воспроизводимые проверки — [tests/README.md](../tests/README.md). Эти документы не дублируются здесь.

Удалять заменённые слои и временные артефакты по мере завершения затронутых подсистем, без отдельного бесконечного этапа полировки.

Прежние внешние сетевые условия остаются после основного пути.

## Что уже существует

- **qbutt:** внутрипроцессные Rust-сервисы, 29 сетевых провайдеров, QML-поиск/история/избранное/источники, библиотека, Share, прямые загрузки и reader. Категории и фильтры работают поверх накопленной выдачи. Bun/Go backend, Cardigann и их продуктовая упаковка удалены; часть старых модулей ещё используется только QA.
- **Чтение:** главы, режимы/fit, настройки, точная позиция, локальные книги, Codex-перевод и обратимый кеш. Есть ограниченный предпреревод следующей главы/страницы и обработка длинных изображений.
- **qplay:** Rust/CXX-Qt/QML с libmpv, GPU policy, framegen, обновление инструментов, Save и перевод субтитров. Старый C#/Lua UI удалён. Свежая локальная установка без Qt SDK, открытие видео, pause/seek/resume и uninstall с сохранением данных приняты. Полная offline-установка ещё не доказана.
- **qcatch:** TypeScript-расширение и Rust host, самостоятельные загрузки и передача в qbutt/qplay. Приняты ограниченные direct/HLS/static-DASH пути; локальный installer и завершение setup CLI исправлены и проверены.

## Приёмка Linux

Первая сборка опубликована для x64, Ubuntu 24.04+ и glibc 2.39+. Существующая Ubuntu WSL обновлена до 24.04.5; отдельный дистрибутив не создавался.

- Content core: нативные Unix broker, Secret Service, защищённые настройки, HTTP-сессии, прямые и сегментированные загрузки, Codex lifecycle проверены. HLS/DASH, отдельные дорожки и стили субтитров приняты на общем FFmpeg 8.1.3; несовместимый системный 6.1 заменён в runtime.
- qbutt: в 1.6.11 закреплены qplay 1.4.2 и qcatch 1.3.8. Для обоих Linux-архивов совпали файлы и контрольные суммы. На установленной сборке проверены открытие окна без SDK, повторная установка и удаление с сохранением настроек. В 1.6.4 поиск, Sources, меню и hover проверены реальным указателем в Xvfb при 1440×900 и 1280×720. Media actor прошёл runtime probe, IPC, file-loaded, stop и reopen с закладкой. Живой Re:Zero через Alloha прошёл запуск, декодирование и перемотку за пределы буфера. Публичная команда проверяет tar.gz, вызывает установщик и регистрирует приложение. Для обновления закройте qbutt и повторите команду.
- Браузерная проверка: proxy/auth, silent/manual, persisted-cookie, reset и отмена проверены также против готового bundle без SDK. Поломанное Qt-перечисление заменено одним URL-scoped каналом DevTools собственного профиля: cookies остаются у Chromium, отдельного хранилища и сетевого debug-порта нет.
- qplay: проигрывание, pause/seek/resume, дорожки, субтитры, апскейл, указатель, fullscreen и геометрия нечётного видео приняты. Установка, повторная установка и удаление сохраняют данные. Полный публичный auto-update 1.3.0 → 1.4.0 принят: приложение само скачивает архив и устанавливает его после закрытия, сохраняя настройки и payload. Нативный NVIDIA framegen с исходной геометрией видео принят в 1.4.0; runtime готовится внутри плеера без Python и отдельного manager.
- qcatch: нативная очередь, IPC, MP3/MP4, отмена, повтор без перезаписи, установка, замена ZIP и удаление проверены. Настоящий Chrome прошёл native messaging, scoped cookies, authenticated POST, точный capture и отказ устаревшего выбора. Реальный popup продолжил загрузку после закрытия; передача в qbutt завершилась точным файлом и записью истории без сессионных данных. Ошибка подготовки потока больше не выдаётся за expired capture. Установщик подтверждает готовность службы и сообщает ошибку запуска; положительный запуск, конфликт порта, отмена и конкурирующий процесс проверены. В Chrome 157 принято публичное автообновление 1.3.3 → 1.3.4. qcatch проверил размер и SHA-256 архива, дождался закрытия popup и обновил нативный host и расширение. Очередь, загруженный файл и язык сохранились. Из публичного popup 1.3.4 один выбранный ролик передан в qplay 1.4.0. На опубликованной сборке подтверждены воспроизведение после закрытия popup, пауза, перемотка указателем и продолжение.
- Хранилище: Linux-анализ, race/fault, scan-only dialog и настоящий authenticated API проверены. Реальный указатель подтвердил scan → обычный Start с сохранением payload. Управляемые repair/staged commit на Linux недоступны: POSIX leases не обеспечивают требуемое владение путями; обычные торренты остаются во владении libtorrent.
- Лендинги: на всех трёх публичных сайтах проверены RU/EN, прямо видимая Linux-команда, точное копирование без `$`, Windows EXE и дополнительные сборки. Единый bootstrap проверяет tar.gz и вызывает существующий установщик. Настоящий публичный `curl | sh` установил qbutt и qplay; повторная установка и удаление сохранили данные.

## Архитектурные решения

Собственная прикладная логика живёт в Rust внутри qbutt; CXX-Qt даёт типизированную границу с Qt. QML отвечает за представление. C++ qBittorrent/libtorrent сохраняет session, peer I/O и storage; qbutt-net остаётся отдельным процессом. Нативные DPAPI и browser broker уже существуют. Переписывать всё ядро ради одного языка не требуется.

Qt 6.12, Quick Controls/Templates и общая палитра — текущая основа. StyleKit не принят для смешанного Widgets/Quick интерфейса: оформление дерева и заголовков не согласовано. Один QML shell через QQuickWidget должен покрывать область модального picker; отдельную накладку поверх соседних Widgets не добавляем. Проверки IME/DPI/стоимости рендера ещё открыты.

Проектные Qt Docs/Live Preview MCP настроены; подтверждение hot reload не является блокером продукта. Отдельная бесполезная preview-сцена удалена. Breaking changes допустимы; миграция старых профилей необязательна, сохранность payload и посторонних данных обязательна.

## Отбор и качество источников

Наш явный список допуска и отдельный читаемый Rust-модуль на провайдера. Внешние адаптеры служат референсом, не загружаются массово и не обновляют код/домены без проверки. Приоритет: RU/EN, полезные японские оригиналы; фильмы, аниме, игры, программы, манга, ранобэ и взрослые каталоги. Нерелевантные региональные, китайские, платные и устойчиво неработающие источники не переносим; у смешанных сайтов проверяем бесплатное покрытие.

Перед добавлением сверять канонический домен, полезность и [Megathread](https://www.reddit.com/r/Piracy/wiki/megathread/), включая [Unsafe Sites](https://www.reddit.com/r/Piracy/wiki/megathread/unsafe-sites/). Сохранённые исключения: thepiratebay.org, 1377x.to, yts.mx, watchsomuch.to, igg-games.com, steamunlocked.net, getintopc.com, haxnode.net. Похожие домены не считаются зеркалами автоматически.

Допуск требует полного search → inspect → resolve → действие, непервого варианта и применимых empty/error/cancel/retry/session сценариев. Один HTTP 200 или AddDialog → Cancel не доказывает законченную загрузку. Для проверки payload использовать контрольный материал; неизвестные игровые EXE запускать не нужно. Один timeout или CAPTCHA не служит основанием выбросить источник.

| C2 | Самостоятельные direct/HLS/DASH загрузки дают реальный файл с правильными audio/subtitles, звуком и seek; отмена дожидается очистки |
| C3 | Точный media/session передаётся в qbutt/qplay без двойной очереди. Устаревший capture требует нового выбора; повтор и удаление продукта не ломают остальные |

Согласованные платформы входят в текущую цель: TikTok, Reddit GIF/видео со звуком, Twitch Clips и Twitch Live → qplay, Instagram, Pinterest, SoundCloud; отдельно определить реальное покрытие Яндекс Музыки/VK Музыки. Распознавание URL и наличие extractor не закрывают платформу. Приёмка требует конечного файла с правильным звуком/длительностью либо воспроизведения, сохранения точного поста/дорожки, повтора и отмены. Текущее покрытие ведётся в [документации qcatch](https://github.com/qbutt-org/qcatch/blob/main/docs/SUPPORTED-SITES.md).

qcatch получает исходные дорожки YouTube через yt-dlp с cookies и обрабатывает их локально. В 1.3.6 yt-dlp проверяет доступность форматов в порядке качества. Из Linux-архива проверены HTTP 403 у предпочтительного формата, сохранение MP3 и MP4, сборка раздельных дорожек, длительность отрезка, отмена и повтор без перезаписи. Прежний стенд Windows также проверил отрезок 00:23–01:05 и видимую ошибку очистки. Для отрезков исходные дорожки пока скачиваются целиком.

Через значок и popup в VM приняты пользовательское TikTok-видео, Twitch-клип, публичный и приватный тестовый SoundCloud-трек, видео Reddit/Instagram/Pinterest с аудио, GIF Reddit/Pinterest и исходные фото TikTok/Instagram/Pinterest. Конечные файлы полностью декодированы; отмена очищает временные данные, повтор сохраняет то же медиа отдельным файлом. Закрытие popup не прервало Twitch-загрузку; повторное открытие TikTok не создало дубль. Внешний видеопин Pinterest не подменяется обложкой, токен приватного SoundCloud не сохраняется в очереди. Форматы и пределы покрытия принадлежат документации qcatch. Музыка фотопоста TikTok отдельно не сохраняется. Текущий extractor Яндекс Музыки завершил контрольный запуск ошибкой метаданных; полный трек не подтверждён. В VK Музыке сайт воспроизводит контрольный трек, но текущая разметка не содержит `data-audio`, qcatch полную дорожку не получает. Источник не принят.

Twitch Live принят в qplay с текущими кадрами и аудиодорожкой, без принудительной начальной позиции; явная позиция обычного видео сохранена. Замена helper не прервала просмотр, временная cookie-сессия удалена после выхода плеера.

Фоновое обновление qcatch и qplay выпущено и принято в VM. qcatch ждёт завершения действий и закрытия popup; qplay устанавливает обновление после закрытия последнего окна. После reload в прежней вкладке приняты direct с субтитрами, открытие публичного видео в qplay и HLS через fetch/XHR с заголовком страницы: файлы декодированы, повтор сохранил тот же медиапоток. В VM расширение само перезагрузилось после установки qcatch 1.2.6. Поток без буфера replay может требовать обновления вкладки; прежний выбор popup сбрасывается. Ручное обновление прежних версий обоих приложений проверено на хосте. Для расширения из внешней unpacked-папки остаётся однократно подключить установленную копию; portable обновляется вручную.

На YouTube доступны открытие в qplay и скачивание qcatch. Реальный popup в VM передал qplay точный ролик без плейлиста и scoped cookies. Перезагрузка расширения сохраняет проверки смены документа и видео. qplay показывает ограниченную причину yt-dlp, включая поздний stderr. Скрытие приватных данных и сброс ошибки при следующем видео проверены через libmpv. Пользователь подтвердил запуск в qplay. Полное скачивание `COX6kiuRvFc` из popup ещё открыто: без авторизованной сессии YouTube требует проверку входа до выдачи дорожек.

Приняты публичный direct MP4 handoff, clear HLS VOD с выбранным audio и browser static DASH SegmentTemplate/Timeline с одной AAC-дорожкой и external VTT. Typed cookies выбранных video/audio/subtitle сохраняют domain/path/Secure/expiry; producer, broker и native queue прошли authenticated HLS/DASH с декодированием и без credentials в БД. Общий Qt receiver принят на созданном медиа; настоящий popup с защищёнными дорожками ещё не принят. Остаются native-helper DASH и настоящий popup/native-проход потерянного ответа; механизм uncertain outcome проверен интеграционно. Embedded TTML, live/encrypted/ranged/multiPeriod не входят в уже подтверждённое покрытие: поддержку определить явно, неподдерживаемое отклонять без ложного успеха. DRM-обход не входит в план.

## Ресурсы и оставшаяся очистка

Бюджеты при сопоставимых условиях: первое видимое окно ≤2 с; два тёплых запуска ≤500 мс каждый; средняя private memory пустого дерева ≤250 MiB; idle CPU ≤2% ядра; каждый WM_NULL ≤50 мс без timeout. Бюджеты первого и тёплого запуска пока не приняты. Измерить первый результат, большие списки и предельный reader. Бюджеты ради прохождения не ослаблять.

Удалить потерявшие потребителей legacy QA-модули, Widgets/QSS/handlers, дубли runtime/profile/discovery и obsolete builds после принятия замены. Проверить отсутствие dev/test overrides в installer; оставшиеся предупреждения strict lint не скрывать новыми allow. Рост диска и длительный idle qcatch после установки ещё не исследованы.

До 20 агентов получают конкретные независимые срезы в отдельных worktree; root владеет общей интеграцией и этим планом. Предпочтение GPT-6.1 Sol/xhigh, разрешённый fallback — 6 Sol, при частых capacity-отказах Astra. Три переиспользуемых build slots, по два compiler jobs; SDK/зависимости общие, Cargo incremental отключён. При передаче слота исключать stale артефакты другого checkout и дубли runtime. VM занята другим проектом: не использовать её и не запускать там процессы. Пользователь разрешил проверки на хосте; использовать изолированные профили и headless/offscreen, когда сценарий это допускает, не перехватывать его мышь и фокус. Linux проверяется в существующей Ubuntu WSL, обновлённой до 24.04.5 LTS; отдельный дистрибутив не создаётся. После проверки освобождать свои процессы, вкладки и ненужные файлы. Ссылки на общие модели/кеш не отменяют запрет reparse внутри продуктового runtime; не удалять их цели и не предполагать работоспособность DLL с SMB.
