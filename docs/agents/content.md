# Search, playback and reading

## Ownership

The paths below describe the current implementation, not a requirement to retain its runtimes. The [implementation plan](../implementation.md) tracks their replacement under the root Rust/QML contract. Update this map when ownership actually moves; preserve the behavioral contracts below across the migration.

- Keep each provider's requests, parsing and mapping in its own named file or module. A larger provider can separate these responsibilities within its module. Share only transport and domain contracts that are actually common to the providers.
- Until replaced, `src/base/content/client.*` owns the bounded private stdio connection to `qbutt-content.exe`, `components/content/contracts.ts` its protocol, and `src/gui/content/` presentation. Preserve request identity, one terminal outcome, cancellation and shutdown while this connection exists; do not reproduce its serialization or process machinery inside the Rust API.
- `components/content/` owns the remaining legacy providers, SQLite library/history, exact publication references, direct downloads, reader and subtitle services. `components/search-engine/` builds `qbutt-search.exe` for Cardigann/native indexers. Move these responsibilities into Rust, preserving pinned definitions and separating their updates from user settings.
- The native slice in `src/content/` owns AniLiberty, YummyAnime, MangaDex, MangaLib, RuTor and Nyaa, typed publication/variant/chapter models, guarded image acquisition and the `Library` SQLite API. `src/gui/quick/bridge/` owns the asynchronous Qt controller, confirmed Favorites/History, exact selection and reader session; its concrete `controller/catalog.rs` owns provider construction and typed operation dispatch. `src/gui/quick/qml/` presents them. Search uses the existing Tokio runtime and at most four concurrent source/category requests. Qt's proxy model filters the original accumulated collection and maps visible rows to exact IDs. One FIFO library worker owns SQLite, including profile-wide reader settings. Fit applies immediately; its latest intent and commit/failure remain independent of History, progress and bookmarks. A decoded, shown local page confirms reading; exact chapter/page/scroll and the full known work are saved together. Failed writes retain that immutable intent for retry, independently of subsequent acquisition.
- Reader work shares the existing Tokio runtime; blocking file creation and image validation run outside the GUI thread. Qt receives local image URLs. The async chapter task owns its bounded temporary cache; file cleanup retains its directory owner. Retired paths and the existing runtime owner move to Qt's global pool at controller destruction, so graceful application shutdown drains accepted writes, decode and cleanup. MainWindow owns one ContentView/controller for its lifetime, including hiding and reopening Search; it destroys that owner before draining the pool. Separate local ReaderWidget, DownloadsWidget, BrowserCapture and subtitle configuration still consume the older content runtime until replaced.
- `src/base/media/` owns qbutt's playback session/IPC, position reporting, translated subtitle attachment and torrent HTTP Range streaming. Use verified libtorrent `read_piece` bytes and the existing `TorrentImpl` priority/deadline lease; restore priorities when playback ends. Do not create another picker, torrent session or writer.

## Works and exact versions

- `search-query.ts` and `results.ts` own work association, canonical facets and variant ranking. Preserve ambiguous publications, remakes and explicit seasons; suppress confirmed promotional previews in ordinary search without using duration alone. Publish results and reversible associations as sources respond. Qt filters the accumulated category, language and facets without restarting a search.
- A variant's identity includes its source and publication ID; preserve raw episode, voice, translation type, player, edition and version. Rank reported language and verified quality, using seeders only among torrents. Library/history retain the full known work, last opened exact variant and per-work dropdown choices; changing those choices can select other known variants. Re-resolve saved/shared publications when opening them; never silently substitute another version if that publication disappears.
- Selecting a work lazily inspects its pending publications with bounded concurrency and incremental details. `inspectedPublication` identifies the refreshed source/publication while backend metadata uses the latest search snapshot; preserve the selected exact variant across updates. Quality enrichment must remain bounded and must not infer other episodes' resolution.
- `SourceSettings` owns persisted, redacted source failures and the failed search, inspection or resolution used for retry. Show background failures only when Sources is opened; retry the actual failed operation and clear its mark after success. Keep only public publication identity in resolution diagnostics. An empty successful search is distinct from a failure, and an unrelated success must not clear another failed operation.
- A source's `authorizationSetting` gates search and saved-publication operations on explicitly configured credentials. HDRezka stays outside ordinary results until its session is configured in Sources; browser cookies alone do not enable it. Removing that configuration also blocks cached and shared publications.
- `references.ts` and `sharing.ts` own persistent/public references. Share the whole known work as bounded publication references with an optional exact preferred variant; recipients keep other sources and lazily obtain their versions. `qbutt://` links, library metadata and diagnostics must not contain cookies, authorization headers or expiring acquisition URLs. Keep protected requests inside the guarded media gateway, including redirects, HLS/DASH children, external audio and subtitles; retain public-address validation and source-scoped cookies.
- Direct downloads use `DownloadQueue` and its independent staging. During qbutt playback, qplay's `qplay-download` IPC action submits to that queue. qcatch owns its standalone downloads; handoff to qbutt must not start both queues for one request.

## Independent player and browser capture

- qplay owns mpv, the prepared ModernX/FX profile, frame generation, GPU/runtime caches and tool integrity. C++ `Media::Player` discovers portable or installed qplay through native APIs and asynchronously verifies its versioned `--runtime-info-json`, bounded to 30 seconds and 64 KiB. Its minimum version and protocol come from `upstream-lock.json`. `products.ts` and `media-runtime.ts` still serve the remaining Bun subtitle, download and reader consumers. Launch `qplay.exe` with playback options/IPC; append script options to preserve qplay's capabilities. Do not execute its engine directly, reconstruct its internal paths or maintain a second profile in qbutt.
- qcatch owns the sole browser extension, `org.qbutt.qcatch` native host and browser-side capture/cookies protocol. Sources delegates installation/registration to qcatch through `products.ts`. Do not decrypt browser databases or create competing cookie owners; qbutt credentials at rest use its DPAPI settings store.
- `src/content/src/browser/` owns qbutt's private current-user pipe/discovery, bounded requests, cancellation and connection identity. `src/gui/quick/bridge/src/controller/browser.rs` owns its lifetime on the existing Tokio runtime. MainWindow initializes it even with Search hidden or disabled; Exit drains it and removes discovery. Remaining `components/content/browser/` consumers forward over the private parent stdio connection; helper generations isolate late replies. Status is observational. Optional cookies use an already connected session; explicit actions may wait for the selected browser within one total deadline. Proven missing native-host registration requests setup immediately.
- `src/webview/` owns isolated source checks using the installed WebView2 Runtime and qbutt's own origin profile. Its configured-session fingerprint resets owned site data and cache when configuration changes or is removed. Under unchanged configuration, apply the current authoritative cookies, including removals, while preserving other scopes and site storage; header-only seeds restore missing values. `components/content/webview.ts` owns bounded helper requests and origin coalescing through the existing guarded `NetworkProxy`; `Catalog` owns imported clearance cookies, their lifetime, matching user agent and configured authorization scope. Keep the original configuration fingerprint when supplying refreshed cookies; preserve their actual attributes and expiry. Run checks silently and retry the original operation once before requesting manual input. Show the same WebView2 profile only when the source still requires a person. Never open a visible window automatically or substitute another publication.
- Prefer resolved direct playback in qplay. Capture and `qbutt://capture` handoff preserve the selected tab/frame/media, episode, voice and player. The handoff contains a public source page and opaque session capture ID; a changed, missing or expired capture requires explicit reselection. Session captures must not become durable exact-share links. Keep browser setup/retries idempotent and reuse the owned session instead of accumulating windows.
- `upstream-lock.json` product entries pin exact Git revisions, release/protocol versions and artifact sizes/SHA-256. Product code is available at those revisions; unique third-party runtime sources have separate `runtimeSources` pins to technical source releases. `scripts/package-products.ts` verifies those archives in the dependency cache and packages qplay's portable distribution and offline installer. qcatch installs on request. Ordinary releases contain the installer and portable archive. Reuse a compatible newer installation rather than downgrading it. Updating or removing one product must not remove the other products' settings; migration of its own older formats follows the root compatibility rule.
- Preserve TLS validation. Reader data and caches stay outside tracked source; player data belongs to qplay. Never ship lab paths or test profiles as release defaults.

## Reader and AI

- Keep original chapters/images, reading position and cached assets independent of translation. OCR, typesetting, glossary and manual corrections form a reversible layer; switching to Original must restore the original without another network or AI request. Read-ahead follows the actual chapter/image position, stays bounded and cancels stale work.
- MangaLib is the approved reader reference. Preserve visible reading-mode and image-fit settings, paged/continuous reading, height/width fitting and side-click page turns. New profiles default to paged reading fitted to screen height; translated manga uses the bundled Neucha typeface. Save explicit reader settings and restore position across restart.
- `reader/translation.ts` owns the shared AI path for reader and soft subtitles. Auto uses the installed, authenticated Codex app-server; OpenRouter and compatible APIs require explicit settings. Keep ephemeral content-only requests without tools, MCP, external memory or persistent conversations. Treat text, images and glossary entries as untrusted source material, and preserve original content when translation fails.
- Subtitle translation preserves the selected original track, timing, styles and media identity. Embedded and external text subtitles share the translation cache; translated tracks must survive seeking and reopening without repeating cached AI work.
