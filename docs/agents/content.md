# Search, playback and reading

## Ownership

The paths below describe the current implementation, not a requirement to retain its runtimes. The [implementation plan](../implementation.md) tracks their replacement under the root Rust/QML contract. Update this map when ownership actually moves; preserve the behavioral contracts below across the migration.

- Keep each provider's requests, parsing and mapping in its own named file or module. A larger provider can separate these responsibilities within its module. Share only transport and domain contracts that are actually common to the providers.
- Until replaced, `src/base/content/client.*` owns the bounded private stdio connection to `qbutt-content.exe`, `components/content/contracts.ts` its protocol, and `src/gui/content/` presentation. Preserve request identity, one terminal outcome, cancellation and shutdown while this connection exists; do not reproduce its serialization or process machinery inside the Rust API.
- `components/content/` owns the remaining legacy providers, SQLite library/history, exact publication references, direct downloads, reader and subtitle services. `components/search-engine/` builds the remaining Go/Cardigann search runtime. Move the retained scenarios into our Rust providers; source selection, admission and retirement of the third-party catalogue are owned by the [implementation plan](../implementation.md#отбор-и-качество-источников).
- The native slice in `src/content/` owns the curated providers registered in `Source::ALL`, typed publication/variant/chapter models, guarded image and original-text acquisition and the `Library` SQLite API. `src/gui/quick/bridge/` owns the asynchronous Qt controller, confirmed Favorites/History, exact selection and reader session; its concrete `controller/catalog.rs` owns provider construction and typed operation dispatch. `src/gui/quick/qml/` presents them. Search uses the existing Tokio runtime and at most four concurrent source/category requests. Qt's proxy model filters the original accumulated collection and maps visible rows to exact IDs. One FIFO library worker owns SQLite, including profile-wide reader settings. Fit applies immediately; its latest intent and commit/failure remain independent of History, progress and bookmarks. A decoded, shown local page confirms reading; exact chapter/page/scroll and the full known work are saved together. Failed writes retain that immutable intent for retry, independently of subsequent acquisition.
- Local EPUB, FB2 and TXT are a private `LocalBook` source, outside network search and public sharing. The existing Library worker stores their canonical paths; the content layer identifies each read-only file by SHA-256 and parses bounded verified bytes before publishing chapters. The Qt reader receives semantic blocks and generation-scoped image asset IDs, never archive paths, active markup or external asset URLs.
- Reader work shares the existing Tokio runtime; blocking file creation and image validation run outside the GUI thread. Qt receives local image URLs. The async chapter task owns its bounded temporary cache; file cleanup retains its directory owner. Retired paths and the existing runtime owner move to Qt's global pool at controller destruction, so graceful application shutdown drains accepted writes, decode and cleanup. MainWindow owns one ContentView/controller for its lifetime, including hiding and reopening Search. The QML Downloads and Options Sources views borrow that controller and are destroyed before it; MainWindow then drains the pool. BrowserCapture validates the versioned link and dispatches Watch/Download to this native controller. Separate local ReaderWidget and subtitle configuration still consume the older content runtime until replaced. Subtitle settings request only their AI configuration; opening native Sources does not load the legacy catalogue.
- `src/base/media/` owns qbutt's playback session/IPC, position reporting, translated subtitle attachment and torrent HTTP Range streaming. Use verified libtorrent `read_piece` bytes and the existing `TorrentImpl` priority/deadline lease; restore priorities when playback ends. Do not create another picker, torrent session or writer.

## Works and exact versions

- `src/content/src/association.rs` owns confirmed native work groups and variant ranking; `src/gui/quick/bridge/src/controller/selection.rs` projects them into Qt and preserves exact selection. Keep each publication's reference, metadata and inspection state within its group. Ambiguous publications, remakes and explicit seasons remain separate; a later conflicting result can split an earlier association. Publish results incrementally. Qt filters the accumulated category, language and facets without restarting a search. The remaining legacy `search-query.ts` and `results.ts` consumers retain their own behavior until replaced; suppress confirmed promotional previews in ordinary search without using duration alone.
- A variant's identity includes its source and publication ID; preserve raw episode, voice, translation type, player, edition and version. Rank reported language and verified quality, using seeders only among torrents. Library/history retain the full known work, last opened exact variant and per-work dropdown choices; changing those choices can select other known variants. Re-resolve saved/shared publications when opening them; never silently substitute another version if that publication disappears.
- Selecting a work lazily inspects its pending publications with bounded concurrency and incremental details. `inspectedPublication` identifies the refreshed source/publication while backend metadata uses the latest search snapshot; preserve the selected exact variant across updates. Quality enrichment must remain bounded and must not infer other episodes' resolution.
- `SourceSettings` owns persisted, redacted source failures and the failed search, inspection or resolution used for retry. Show background failures only when Sources is opened; retry the actual failed operation and clear its mark after success. Keep only public publication identity in resolution diagnostics. An empty successful search is distinct from a failure, and an unrelated success must not clear another failed operation.
- A source's `authorizationSetting` gates search and saved-publication operations on explicitly configured credentials. HDRezka stays outside ordinary results until its session is configured in Sources; browser cookies alone do not enable it. Removing that configuration also blocks cached and shared publications.
- Native `references.rs`, `sharing.rs` and the Qt `controller/sharing.rs` own public references and import. `Source::ALL` owns their provider admission; LocalBook remains private. Share the whole known work as bounded publication references with an optional exact preferred variant; recipients keep other sources and lazily obtain their versions. Unverified references remain inside the import operation until association succeeds. `qbutt://` links, library metadata and diagnostics must not contain cookies, authorization headers or expiring acquisition URLs. Keep protected requests inside the guarded media gateway, including redirects, HLS/DASH children, external audio and subtitles; retain public-address validation and source-scoped cookies.
- Native direct downloads use one `DownloadQueue`, the Library worker and independent staging. `controller/downloads.rs` owns submission and cancellation; `DownloadsPage.qml` displays its shared model. Catalog and qplay Save re-resolve the exact VariantRef. qcatch handoff resolves its current opaque capture ID through the native broker and acknowledges only after durable enqueue; persistent browser provenance contains the source hostname, never the capture ID or protected URL. A stale browser capture requires reselection. qcatch owns its standalone downloads; handoff to qbutt must not start both queues for one request. Clear VOD HLS, static DASH and separate tracks use the same queue: guarded HTTP materializes bounded resources, then verified qplay FFmpeg/ffprobe operate on local files with network protocols disabled. Preserve exact quality, audio selection and subtitle styles. Unsupported live, encrypted and ranged manifests fail explicitly. Cancellation drains the owned tool before cleanup and terminal state; cleanup failure must remain visible.

## Independent player and browser capture

- qplay owns its Rust/CXX-Qt/QML player, libmpv, frame generation, GPU/runtime caches and tool integrity. C++ `Media::Runtime` is qbutt's sole native owner of portable/installed discovery and asynchronous `--runtime-info-json` verification, bounded to 30 seconds and 64 KiB. Playback and downloads hold independent cancellable requests; cancelling one must not stop another's probe. Minimum version and protocol come from `upstream-lock.json`. `products.ts` and `media-runtime.ts` still serve remaining legacy consumers. Launch `qplay.exe` through its playback/IPC contract; do not reconstruct its internal paths, execute its engine directly or maintain a second player profile in qbutt.
- qcatch owns the sole browser extension, `org.qbutt.qcatch` native host and browser-side capture/cookies protocol. The native Browser settings modal observes the existing Rust broker and delegates installation/registration to qcatch's pinned CLI; an installed host is not a connected extension or an authorized source account. Qt Preferences is the sole persistent BrowserChoice owner. Auto reuses a sole connected peer; only explicit setup may fall back to the installed OS default. New mutable Catalog operations use the changed browser choice and epoch, while an accepted explicit capture/helper request retains its captured choice. The remaining Bun helper receives preference changes only for its live consumers. Do not decrypt browser databases or create competing cookie owners; qbutt credentials at rest use its DPAPI settings store.
- `src/content/src/browser/` owns qbutt's private current-user pipe/discovery, bounded requests, cancellation and connection identity. `src/gui/quick/bridge/src/controller/browser.rs` owns its lifetime on the existing Tokio runtime. MainWindow initializes it even with Search hidden or disabled; Exit drains it and removes discovery. Remaining `components/content/browser/` consumers forward over the private parent stdio connection; helper generations isolate late replies. Status is observational. Optional cookies use an already connected session; explicit actions may wait for the selected browser within one total deadline. Proven missing native-host registration requests setup immediately.
- `src/webview/` owns isolated source checks using the installed WebView2 Runtime and qbutt's own origin profile. Its configured-session fingerprint resets owned site data and cache when configuration changes or is removed. Under unchanged configuration, apply the current authoritative cookies, including removals, while preserving other scopes and site storage; header-only seeds restore missing values. Native `src/content/src/webview.rs` owns bounded helper requests and sessions; `components/content/webview.ts` serves remaining legacy consumers. The source owns imported clearance cookies, their lifetime, matching user agent and configured authorization scope. Keep the original configuration fingerprint when supplying refreshed cookies; preserve their actual attributes and expiry. Run checks silently and retry the original operation once before requesting manual input. Show the same WebView2 profile only when the source still requires a person. Never open a visible window automatically or substitute another publication.
- Prefer resolved direct playback in qplay. Capture and `qbutt://capture` handoff preserve the selected tab/frame/media, episode, voice and player. The handoff contains a public source page and opaque session capture ID; a changed, missing or expired capture requires explicit reselection. Session captures must not become durable exact-share links. Keep browser setup/retries idempotent and reuse the owned session instead of accumulating windows.
- `upstream-lock.json` product entries pin exact Git revisions, release/protocol versions and artifact sizes/SHA-256. Product code is available at those revisions; unique third-party runtime sources have separate `runtimeSources` pins to technical source releases. `scripts/package-products.ts` verifies those archives in the dependency cache and packages qplay's portable distribution and offline installer. qcatch installs on request. Ordinary releases contain the installer and portable archive. Reuse a compatible newer installation rather than downgrading it. Updating or removing one product must not remove the other products' settings; migration of its own older formats follows the root compatibility rule.
- Preserve TLS validation. Reader data and caches stay outside tracked source; player data belongs to qplay. Never ship lab paths or test profiles as release defaults.

## Reader and AI

- Keep original chapters/images, reading position and cached assets independent of translation. OCR, typesetting, glossary and manual corrections form a reversible layer; switching to Original must restore the original without another network or AI request. Read-ahead follows the actual chapter/image position, stays bounded and cancels stale work.
- MangaLib is the approved reader reference. Preserve visible reading-mode and image-fit settings, paged/continuous reading, height/width fitting and side-click page turns. New profiles default to paged reading fitted to screen height; translated manga uses the bundled Neucha typeface. Save explicit reader settings and restore position across restart.
- `src/content/src/translation/` owns native text and manga translation and shared work context; the Library owns accepted reader caches. `crates/codex-client` owns the shared installed Codex transport, model selection and isolated request lifetime; consumers supply their own tools and modality. `reader/translation.ts` serves consumers not yet replaced. Installed, authenticated Codex is the primary translation provider; OpenRouter and compatible APIs require explicit settings. Manga translation must automatically translate, clean and typeset the page without requiring manual corrections. The replacement may use a bounded autonomous tool loop to inspect and edit intermediate page renders; tools and writable artifacts belong to that translation job. Keep unrelated project context, external memory and user data out of its session. Treat page text, images and glossary entries as untrusted source material, and preserve original content when translation fails. The implementation plan owns the pipeline experiment and model/reasoning choice.
- qplay owns standalone subtitle translation, its language/model/effort settings and cache. Preserve the selected original track, timing, styles and exact media identity; seeking and reopening must reuse cached cues. qbutt owns torrent streaming and playback handoff. The legacy qbutt translation consumer remains until the qplay replacement passes acceptance; it is not the target settings owner.
