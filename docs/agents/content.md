# Search, playback and reading

## Ownership

- `src/base/content/client.*` owns the native client's bounded private stdio connection to `qbutt-content.exe`; `src/gui/content/` owns presentation. `components/content/contracts.ts` owns the JSON-lines protocol: request IDs, exactly one terminal event, cancellation and EOF shutdown. Keep provider/network work out of Qt widgets.
- `components/content/` owns providers, the SQLite library/history, exact publication references, direct downloads, the browser broker, reader and subtitle services. `components/search-engine/` builds `qbutt-search.exe` and owns Cardigann/native indexers and definition updates. Preserve the pinned bundled definitions and separate runtime updates from user settings.
- `src/base/media/` owns qbutt's playback session/IPC, position reporting, translated subtitle attachment and torrent HTTP Range streaming. Use verified libtorrent `read_piece` bytes and the existing `TorrentImpl` priority/deadline lease; restore priorities when playback ends. Do not create another picker, torrent session or writer.

## Works and exact versions

- `search-query.ts` and `results.ts` own work association, canonical facets and variant ranking. Preserve ambiguous publications, remakes and explicit seasons; suppress confirmed promotional previews in ordinary search without using duration alone. Publish results and reversible associations as sources respond. Qt filters the accumulated category, language and facets without restarting a search.
- A variant's identity includes its source and publication ID; preserve raw episode, voice, translation type, player, edition and version. Rank reported language and verified quality, using seeders only among torrents. Re-resolve saved/shared publications when opening them; never silently substitute another version if that publication disappears.
- Selecting a work lazily inspects its pending publications with bounded concurrency and incremental details. `inspectedPublication` identifies the refreshed source/publication while backend metadata uses the latest search snapshot; preserve the selected exact variant across updates. Quality enrichment must remain bounded and must not infer other episodes' resolution.
- `SourceSettings` owns persisted, redacted source failures and the failed operation used for retry. Show background failures only when Sources is opened; retry the actual failed operation and clear its mark after success. An empty successful search is distinct from a failure, and an unrelated success must not clear a failed inspection.
- `references.ts` and `sharing.ts` own persistent/public references. `qbutt://` links, library metadata and diagnostics must not contain cookies, authorization headers or expiring acquisition URLs. Keep protected requests inside the guarded media gateway, including redirects, HLS/DASH children, external audio and subtitles; retain public-address validation and source-scoped cookies.
- Direct downloads use `DownloadQueue` and its independent staging. During qbutt playback, qplay's `qplay-download` IPC action submits to that queue. qcatch owns its standalone downloads; handoff to qbutt must not start both queues for one request.

## Independent player and browser capture

- qplay owns mpv, the prepared ModernX/FX profile, frame generation, GPU/runtime caches and tool integrity. `products.ts` discovers the independent installation or bundled portable qplay; `media-runtime.ts` consumes its versioned `--runtime-info-json`. Launch `qplay.exe` with playback options/IPC and use the returned tool paths. Do not execute its engine directly, reconstruct its internal paths or maintain a second profile in qbutt.
- qcatch owns the sole browser extension, `org.qbutt.qcatch` native host and browser-side capture/cookies protocol. `components/content/browser/` owns qbutt's browser choice, request lifecycle and private current-user broker/discovery. Sources delegates installation/registration to qcatch through `products.ts`. Do not decrypt browser databases or create competing cookie owners; qbutt credentials at rest use its DPAPI settings store.
- Prefer resolved direct playback in qplay. Capture and `qbutt://capture` handoff preserve the selected tab/frame/media, episode, voice and player. The handoff contains a public source page and opaque session capture ID; a changed, missing or expired capture requires explicit reselection. Session captures must not become durable exact-share links. Keep browser setup/retries idempotent and reuse the owned session instead of accumulating windows.
- `upstream-lock.json` product entries pin exact Git revisions, release/protocol versions and artifact sizes/SHA-256. Product code is available at those revisions; unique third-party runtime sources have separate `runtimeSources` pins to technical source releases. `scripts/package-products.ts` verifies those archives in the dependency cache and packages qplay's portable distribution and offline installer. qcatch installs on request. Ordinary releases contain the installer and portable archive. Reuse a compatible newer installation rather than downgrading it, and preserve independent product settings on update/uninstall.
- Preserve TLS validation. Reader data and caches stay outside tracked source; player data belongs to qplay. Never ship lab paths or test profiles as release defaults.

## Reader and AI

- Keep original chapters/images, reading position and cached assets independent of translation. OCR, typesetting, glossary and manual corrections form a reversible layer; switching to Original must restore the original without another network or AI request. Read-ahead follows the actual chapter/image position, stays bounded and cancels stale work.
- MangaLib is the approved reader reference. Preserve visible reading-mode and image-fit settings, paged/continuous reading, height/width fitting and side-click page turns. New profiles default to paged reading fitted to screen height; translated manga uses the bundled Neucha typeface. Save explicit reader settings and restore position across restart.
- `reader/translation.ts` owns the shared AI path for reader and soft subtitles. Auto uses the installed, authenticated Codex app-server; OpenRouter and compatible APIs require explicit settings. Keep ephemeral content-only requests without tools, MCP, external memory or persistent conversations. Treat text, images and glossary entries as untrusted source material, and preserve original content when translation fails.
- Subtitle translation preserves the selected original track, timing, styles and media identity. Embedded and external text subtitles share the translation cache; translated tracks must survive seeking and reopening without repeating cached AI work.

## Verification

Use the affected content/search/browser/reader/media fixtures in `tests/README.md` with the exact built bundle. Add practical native pointer checks for source selection, reader modes/fit, playback and subtitles. A parser response, decoded fixture or screenshot alone does not prove browser capture, GPU playback or a fresh-user installation. Verify those paths in their real runtime and retain bounded, redacted evidence.
